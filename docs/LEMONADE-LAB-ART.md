# Lemonade Lab artwork and motion

All eighty market missions now use illustrated venue settings, a complete wooden lemonade stand, recognizable glass pitcher, lemon bowl and closed cashbox, plus a two-pose vendor. Ten venue pictures match the ten named locations repeated across the eight mission chapters. Four-day free play has separate sunny, rainy, festival and quiet-neighborhood settings. The shared introduction uses a welcome plaza, the same vendor and the same pitcher.

## Quantities, results and learning behavior

The cup pictures always describe the **currently selected batch**, including after a run. Each selected cup has exactly one picture. Changing the stock selector updates only that picture panel, preserving control focus and native selections. Demand, sales, leftovers, budgets, costs, revenue, profit and goals remain native text produced by the original game model. No customer crowd or generated price labels imply a different quantity.

A valid market run gives the vendor a small welcoming wave and the selected cup pictures a brief response, including when the player needs to revise the plan. The existing result text distinguishes goal success from a retry. Over-budget attempts retain the current scene and result state without inventing a sale. Both site and device reduced-motion settings stop the reactions while keeping all objects visible.

Free play retains its original **next-day forecast** after each sale; the ledger records completed days. The caption explicitly says Forecast, and after day four Final forecast. This avoids presenting the next day's artwork as a picture of the previous sale. Original four-day arithmetic, the 14-coin start, supply costs, mission goals, native controls, checkpoint format, eighty-mission progression, rewards, completion and replay remain unchanged. The game continues to use fictional coins and a simplified toy market model.

Native labels, field values, option menus and result text retain their light/dark/high-contrast styles. Labels sit outside the artwork. The stand, vendor and batch reflow at 320 pixels and 200% text, with a focusable scrolling business ledger for the five-column table. The skip link hides by its own height until focused so enlarged wrapped text cannot overlay the board.

## Assets and provenance

Twenty-one new local WebP files (about 1.33 MiB) include fifteen 832 × 468 environments in `assets/world-motion/backgrounds/lemon-{setting}.webp`, a 640 × 320 vendor sheet in `assets/world-motion/characters/lemon-vendor.webp`, and a 256 × 256 shared pitcher in `assets/world-motion/objects/lemon-pitcher.webp`. The 384 × 384 stand and three other 256 × 256 props are in `games/lemonade-lab/art/`.

Seven original sheets/atlases were generated with the built-in image generator using the briefs below. Production processing is deterministic atlas cropping, transparent padding, resizing and WebP encoding. Generated alpha is preserved. The stand retains its full square framing so the separately rendered props align with the countertop. All illustrations ship locally; no new runtime dependency or external image service is added. Code and original artwork use the repository's existing MIT license.

## Verification

`npm run validate` checks the existing repository contracts. Focused desktop/phone tests in `tests/browser/lemonade-art.spec.mjs` check cup quantities, retained select focus, actual vendor/cup animation frames, both reduced-motion preferences, unsuccessful and successful plans, saved mission resume, all four forecasts, exact ledger rows, free-play and mission budget rejection, contrast and enlarged-text reflow. Finite animation frames are sampled at fixed points and playback restored, avoiding dependence on two adjacent browser frames.

The full eighty-mission campaign in `tests/browser/skill-worlds.spec.mjs` checks every venue, selected batch count, native demand/sales/leftovers/profit result, saved advancement, completion and replay. Existing four-day free play, saved creative mission, native dropdown contrast, shared-scene and general contrast checks remain relevant. Functional checks are supplemented by visual inspection of actual desktop/phone scenes and sprite transparency.
